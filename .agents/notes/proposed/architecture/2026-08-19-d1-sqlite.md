# Agent Note: D1 / SQLite via Drizzle

ID: ADR-0004
Status: proposed

## Problem

The product needs one transactional store per environment on Cloudflare.
PostgreSQL-shaped assumptions would not run on D1.

## Proposal

Use Drizzle's SQLite dialect and only D1-supported SQL. Reviewed committed
SQL is the deployment artifact.

## Rationale

Required platform, managed, sufficient for 2–3 users.

## Alternatives considered

- **Status quo (browser `localStorage` / Google Sheets):** rejected; last
  write wins and cannot enforce invariants.
- **PostgreSQL:** rejected until capacity evidence appears.
- **KV-only:** rejected; we need relational invariants and transactions.

## Impact

- **Security:** tenant scope must be in SQL and use cases, not only in
  clients. No `drizzle-kit push` against production.
- **Operations:** reviewed SQL migrations; never migrate at Worker startup.
- **Data:** one D1 database per environment; no production data in Git.

## Affected components

`packages/db`, Worker D1 binding, migration runbooks.

Human architectural reviewer. Not self-approved.
